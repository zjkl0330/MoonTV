# 浏览器兼容性（老浏览器支持）

本文说明 MoonTV 现在支持到什么程度的老浏览器、具体做了什么、以及怎么自己验证。

---

## 1. 兼容基线

| 浏览器                               | 最低版本 | 状态                                   |
| ------------------------------------ | -------- | -------------------------------------- |
| Chrome / Edge(Chromium)              | 61       | 可用（功能降级见第 4 节）              |
| Chrome for Android / Android WebView | 61       | 可用（视频建议 66+）                   |
| Safari (macOS)                       | 10.1     | 可用                                   |
| Safari (iOS / iPadOS)                | 10.3     | 可用（原生 HLS 播放）                  |
| Firefox                              | 60 (ESR) | 可用                                   |
| Opera                                | 48       | 可用                                   |
| Samsung Internet                     | 8.2      | 可用                                   |
| IE11 / Chrome < 61 / Safari < 10.1   | 不支持   | 显示「浏览器版本过低」提示页，不再白屏 |

**为什么卡在 Chrome 61 / Safari 10.1？** 这是「支持 ES Module」的分水岭。Next.js 14 只产出
`<script type="module">`，没有 nomodule 回退包，比这更老的浏览器连 React 都启动不了 —— 这不是
polyfill 能修的，只能在 `src/app/layout.tsx` 里挂一段 ES5 的提示脚本兜底。

---

## 2. 四层改动

### 第一层：构建目标（真正起作用的一层）

`package.json` 里新增 `browserslist`：

```json
"browserslist": [
  "chrome >= 61", "and_chr >= 61", "edge >= 79", "firefox >= 60",
  "safari >= 10.1", "ios_saf >= 10.3", "opera >= 48", "samsung >= 8.2",
  "not dead"
]
```

这一处配置同时喂给三方：

- **SWC**：把 TS/JS 降级到目标浏览器都能跑（async/await、可选链、类字段等）；
- **autoprefixer**：自动补 `-webkit-`（`backdrop-filter`、`user-select` 等）；
- **Tailwind 3.4**：有老目标时它会自动把 `rgb(0 0 0 / .5)` 输出成 `rgba(0, 0, 0, .5)` ——
  这条最关键，否则老浏览器上所有带透明度的背景色会整条失效。

> 改这个列表 = 改整站兼容下限，也会改变包体积。往下加之前先想清楚要不要背 ES5 的转换成本。

### 第二层：CSS 降级（`scripts/postcss-legacy.js`）

挂在 `postcss.config.js` 里，顺序是 `tailwind → postcss-legacy → autoprefixer`：

| 处理                                      | 原因                                 | 产出                                                        |
| ----------------------------------------- | ------------------------------------ | ----------------------------------------------------------- |
| `rgb/hsl` 空格+斜杠语法 → 逗号语法        | Chrome 65 / Safari 12.1 才有新语法   | `rgba(0, 0, 0, .5)`，alpha 是 `var()` 时同样成立            |
| `inset: 0` → 展开 `top/right/bottom/left` | Chrome 87 / Safari 14.1 才有 `inset` | 旧声明放在前面，现代浏览器仍走 `inset`                      |
| `aspect-ratio: 2/3` → `@supports` 兜底    | Chrome 88 / Safari 15 才有           | `padding-top: 150%` + 子元素绝对定位，海报卡片不再塌成 0 高 |

### 第三层：运行时补丁（`src/lib/legacy/`）

| 文件                  | 作用                                                                                                                                                                                                                              |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `browser-support.ts`  | 纯函数的能力探测：`readBrowserEnv`、`hlsStrategy`、`shouldUseHlsWorker`                                                                                                                                                           |
| `polyfills.ts`        | 缺失才安装的补丁：`Promise.allSettled/finally/any`、`String.replaceAll`、`Object.fromEntries`、`Array.at/flat/flatMap`、`AbortController`（含 fetch signal 包装）、`Element.closest`、`scrollTo({left,top})`、`queueMicrotask` 等 |
| `observers.ts`        | `ResizeObserver` / `IntersectionObserver` 兜底（滚动 + 轮询实现）                                                                                                                                                                 |
| `clipboard.ts`        | `copyText()`：优先 `navigator.clipboard`，不行就 `execCommand('copy')`                                                                                                                                                            |
| `no-module-notice.ts` | 给不支持 ES Module 的浏览器的 ES5 提示脚本                                                                                                                                                                                        |

补丁由 `src/components/LegacySupport.tsx` 引入（layout 里挂载），并在补丁装完之后再探测一次能力，
缺关键能力时底部弹一条可关闭的提示。

### 第四层：业务代码里的降级点

- `src/lib/player/artPlayerOptions.ts`
  - hls.js 的 `enableWorker` 改为按能力决定：Android ≤ 5、Chrome < 53、无 `Worker` 时关掉
    （老 WebView 上 blob worker 会直接抛错，关了至少能播）。
  - 没有 MSE 也没有原生 HLS 时，错误详情带 `reason: 'no-mse'`，`describeHlsError` 会给出
    「缺少 MediaSource，建议升级浏览器或改用系统播放器」，而不是黑屏。
- `src/app/play/page.tsx`：复制播放直链改用 `copyText()`，老浏览器不再静默失败。
- `src/app/layout.tsx`：`<script nomodule>` 提示 + `<LegacySupport />`。

## 3. 缺什么会怎样（分级降级）

| 缺失能力             | 影响                 | 处理                                                                       |
| -------------------- | -------------------- | -------------------------------------------------------------------------- |
| ES Module            | 整站白屏             | `nomodule` 脚本给出提示页（无法自动修复）                                  |
| Promise / fetch      | 整站白屏             | 低于基线，同样只给提示                                                     |
| MediaSource          | 不能在线播放         | iOS/Safari 走原生 HLS；其它浏览器提示改用系统播放器                        |
| Web Worker           | 播放卡顿             | 自动关掉 hls.js worker                                                     |
| IntersectionObserver | 豆瓣页无限滚动失效   | 用滚动监听兜底                                                             |
| ResizeObserver       | 横向列表箭头状态不准 | 用轮询兜底                                                                 |
| AbortController      | 请求超时/取消不生效  | 伪造 signal + 包装 fetch（请求本身无法真正中断，只保证 Promise 会 reject） |
| clipboard            | 复制按钮失效         | `execCommand('copy')` 兜底                                                 |
| `scrollTo` options   | 切集按钮不居中       | 降级为瞬移（无平滑动画）                                                   |

## 4. 已知限制

1. **flex `gap` 没做兜底**。老浏览器（Chrome < 84 / Safari < 14.1）会把 `gap` 当 0，表现为「间距没了」，
   布局不会错位。要正确模拟得逐个容器算 margin，收益远小于风险，故意不做。
2. **`AbortController` 补丁不会真正中断网络请求**，只是让 Promise 按超时 reject，请求会在后台跑完。
3. **PWA 离线缓存**依赖 Service Worker，老浏览器装不上，不影响在线使用。
4. **`backdrop-filter` 只到 Safari 9+ 的 `-webkit-` 前缀**，更老的内核上只是少了毛玻璃效果。
5. 低于基线（IE11 等）**不提供可用页面**，只有提示页 —— Next 14 没有 nomodule 产物，这是框架层面的硬限制。

## 5. 怎么验证

```bash
# 1. 类型 + 单测（含补丁、观察器、postcss 插件）
pnpm typecheck
pnpm test

# 2. CSS 产物校验（不跑整包构建，直接跑构建里那段 PostCSS）
pnpm verify:legacy

# 3. 真实构建
pnpm build
```

`pnpm verify:legacy` 会断言 7 件事，任何一条不满足就 exit 1：

```
✅ 没有残留 rgb/hsl 空格+斜杠语法
✅ 透明度颜色是 rgba() 旧语法
✅ inset 展开成四向定位
✅ aspect-ratio 有 @supports 兜底
✅ 兜底里 padding-top 比例正确
✅ backdrop-filter 带 -webkit- 前缀
✅ 渐变色标仍是旧语法
```

真机验证建议至少覆盖：iOS 10/11 Safari、Android 5~7 WebView（Chrome 60 左右）、Firefox 60 ESR。

## 6. 想继续往下兼容怎么办

1. 先把 `browserslist` 往下调（例如 `safari >= 9`），跑 `pnpm build` 看包体积涨多少；
2. 低于 Chrome 61 / Safari 10.1 的浏览器**必须**另外出一套 nomodule 打包产物，否则只是徒增体积；
3. 新增的老浏览器补丁一律放进 `src/lib/legacy/`，并补一条 `src/lib/legacy/__tests__` 单测 ——
   补丁是最容易在边缘浏览器上「自己把页面搞崩」的代码。
